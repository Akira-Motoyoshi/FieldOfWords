## 2. Day 1 以降の投稿文【確定】

ファイル: `posts/make_post.py`、`posts/xlen.py`（X換算の文字数計算）、`posts/test_post_state.json`（テスト用）、`posts/sample_day1/`（出力例）

使い方: `python3 make_post.py --state garden/state.json --out posts_out`（`xlen.py` と同じフォルダ）。媒体ごとに `<媒体>.txt` と `post_report.json` を出力する。

| 媒体 | 版 | 上限 |
|---|---|---|
| X | 短縮版（区切りを「／」、判定の件数は3項目） | X換算 280 |
| Instagram・Threads | 通常版 | 300字 |

**構成（上から）**: 見出し（`【ことばのかだん Day n】`）→ 自庭の様子 → 判定の件数 → 出来事 → 順位 → 締め（`おはなでいっぱいにしてね!`）

- 出来事: 毒花が咲いた（種類と、チクチクの種類名のみ）／浄化された／「あと◯件のふわふわで◯◯が◯◯に変わります」／開花／リポスト数と虹まであと何件
- **原文は一切載せない。** 件数と種類名だけ。
- 長すぎる場合は、優先度の低い行から削る（リポスト、開花、あふれた毒花、浄化の予告の順）。**見出し・自庭・順位の3行は必ず残る。**
- 順位は、生育ステージ→健康度→開花数。同点は同率でまとめる（例: `1位 Instagram・Threads 3位 X`）。
- 検証: 乱数で作った500通りの状態で、上限超過0件。Xの最大は280ちょうど。
- 「判定はAIの解釈」の断り書きは入れない（#04 の決定どおり）。

**state.json に追加で必要なフィールド**（Muse が毎日の更新で書く）
| フィールド | 内容 |
|---|---|
| `yesterday_tally` | `soft` / `prickly` / `neutral` / `out_of_scope` / `excluded` の件数（既存） |
| `events_today` | `{"new_poison": [species…], "purified": [species…], "bloomed": [species…]}`。省略可 |
| `purify_pool` | ふわふわの累計（3で浄化、既存）。「あと◯件」の計算に使う |
| `totals.reposts` | リポスト累計。取得不可なら `unavailable_metrics` に `"reposts"` を入れる |
| `unavailable_metrics` | 取得できない指標（既存）。`"comment_text"` を含むと、判定の行が「この媒体では取得できません」になる |

### 発見した問題（X）
**Xでコメント本文が取れない場合、浄化は起きない。** ふわふわを数えられないため。この場合、文面には「あと◯件のふわふわで…」を**書かない**ようにした（約束できないため）。ただし毒花の芽吹きも発生しないので、Xの庭は反応（いいね・リポスト）だけで育つことになる。取得可否の実機確認が必要（下の未決1）。

## 3. 判定テスト【依頼】

ファイル: `judge/judge_prompt.md`（判定用の指示文）、`judge/judge_testset.json`（32件）、`judge/score_judgement.py`（採点）

手順:
1. `judge_prompt.md` を指示として、`judge_testset.json` の32件を1件ずつ判定する。出力は、各件 `{"id","target","exclusion","tone","type","confidence"}` の JSON のみ（原文は出力しない）。
2. 結果を `muse_output.json`（32件のリスト）にまとめ、`python3 score_judgement.py --testset judge_testset.json --result muse_output.json` を実行する。
3. 合否とずれた件を、ユーザーに報告する。

合格基準（すべて満たす）: 集計外の見逃し0件／善意への毒花の誤判定0件／正答率85%以上／19番・23番は中立／31番は `self_harm` として報告対象。

注意:
- 28〜32番は、実文を載せず**内容の説明文**で代用している。説明文として判定してよい。
- 採点側は、合成データで動作確認済み（完璧な出力は合格、見逃しや誤判定は不合格になる）。**Muse の実際の判定は未実行。**
- `confidence: low` は、採点上も運用上も中立として扱う。迷ったら low にする。
- 不合格の場合は、`judge_prompt.md` の該当箇所を直して再実行する。直した内容はユーザーに報告する。
