## 1. ゴール

**企画**: SNSごとに架空の庭を1つ作り、その媒体の住人の反応だけで育てる連載。インプレッション=日光、いいね=水、ふわふわ言葉（やさしいコメント）=栄養で、きれいな花が育つ。チクチク言葉は毒花を咲かせるが、ふわふわ言葉が重なると普通の花に浄化される。毎日、全庭の状態と順位を発表する。

**媒体と経路**: X（Buffer）／Instagram（コネクタ）／Threads（コネクタ）。投稿は1日1件/媒体。

**ハッカソンの必須条件**: ソロ／Museのみで自動化／**公開SNS投稿3点以上**／スクショと Permalink を Medium に埋め込む／個人情報を漏らさない／CC BY 4.0／発表は 2026-11-24（火）ゼミ。

**日程**: 11/21 Day 0 ／ 11/22 Day 1 ／ 11/23 Day 2 ／ 11/23〜24 Medium 記事 ／ 11/24 発表。
**最低ライン**: 3媒体の Day 0 が公開されれば、公開投稿3点の条件は満たせる。まず Day 0 を3媒体に出すことが最優先。

### 主なルール（要約。正本は RULES.md）
- ふわふわ1件 → 品種に応じた花を1輪植える（栄養）＋浄化カウント+1（両取り。**確定**）。ふわふわ3件で毒花1輪（古い順）が浄化される。
- チクチク1件 → 毒花が芽吹く。健康度が下がる。報酬なし・即死なし・名指しなし。
- リポスト → 野の花の芽。新規フォロワー → 植えられる数+1（初期3、上限14）。いいね → 水。インプレッション → 日光。
- 順位：生育ステージ→健康度→開花数。
- 毒花は画像に1日2輪まで。超過分は「ナゾのカビ園」1つにまとめる。大型（ラフレシア・ブラックホール花・カビ園）は後列に置く。
- 数値（日光Lv、水、健康度の増減、マイルストーン）は**暫定**。実行して様子を見て、ユーザーと調整する。
- 返信の連鎖なし。**Museによる自動返信もしない**。
- 「判定はAIの解釈」の断り書きは、**書かない**（ユーザー決定）。

### 判定ルール（要約。詳細は judge/judge_prompt.md）
優先順位は**集計外 > 対象外 > チクチク／ふわふわ > 中立**。1コメント1判定、迷ったら中立。集計外は、差別・脅迫・個人攻撃・自傷を促す言葉。自傷に関わるものは、種別と日付だけ `alerts_for_owner` に記録し、**ユーザーに報告して人が判断する**。

### タスクC：X のコメントと数字が取れるかの確認
Day 0 の X 投稿が公開されたら、次の順に確認する。**結果は、事実だけを報告する（推測で埋めない）。**

背景: Buffer の資料が食い違っている。公式の紹介ページは「X の分析は全プランで無料」と読めるが、ヘルプ記事は「X の送信済み投稿のデータは有料プランが必要で、無料プランでは取れない」と読める。Buffer の Community 機能（コメントを一覧する画面）は X も対象で、全プランで使える。

1. **数字**: Buffer の Publish → Sent タブで、X チャンネルの Day 0 投稿に、インプレッション・いいね・リポスト・コメント数が出るか。
2. **コメント本文**: ユーザーに、**別のアカウント**（あなたやユーザー本人の個人アカウントではなく、テスト用か友人のもの）から Day 0 の投稿へ「テスト」と返信してもらう。数分後、Buffer の Community → X で、本文つきで表示されるか。
3. **自動で読めるか**: あなたのツールで、Community の画面から読めるか。無理なら、X の投稿ページ（Permalink）から、返信の本文と数字が読めるか。ログインが必要なら、ユーザーに依頼する。
4. **記録**: 取れない指標は、X の `unavailable_metrics` に入れる（例: `["comment_text"]`、数字も取れないなら `["impressions","likes","reposts","comment_text"]`）。
5. **判断が必要なら、ユーザーに選んでもらう**: 数字も取れない場合の選択肢は、(a) X の投稿ごとの分析ページをブラウザで読む、(b) Buffer の有料プラン（**予算0円の条件に反する**ので最後の手段）。

**取れない場合の影響**: コメント本文が読めないと、X の庭にはふわふわ・チクチクが発生せず、毒花も浄化も起きない（反応の数だけで育つ）。`make_post.py` は、この場合、X の文面から「あと◯件のふわふわで…」を自動で外す。

### タスクD：判定テスト

## 4. 毎日の手順（Day 1 以降。cron 09:00）

1. `state.json` と `posts/log.jsonl` を読む（重複投稿の防止）
2. 媒体ごとに前日分の反応を収集する（取れない指標は `unavailable_metrics` に記録し、推測で埋めない）
3. コメントを `judge/judge_prompt.md` で判定し、件数だけを集計する（原文は保存しない）。自傷に関わるものは `alerts_for_owner` に記録してユーザーに報告
4. `RULES.md` に従って `state.json` を更新する（成長、毒花、浄化、順位）。新しく植えるときは `compose.choose_slot()` で置き場所を決め、チューリップは `compose.tulip_color()` で色を決めて plot に保存する
5. 画像を作る：`python3 compose.py --state garden/state.json --assets assets --out out --gif`。浄化が起きた日は `purify_scene.py` で、前後の2コマ画像とGIFも作る
6. 投稿文を作る：`python3 make_post.py --state garden/state.json --out posts_out`（Xは短縮版、他は通常版。原文は載せず、件数と種類名のみ）
7. 各経路で投稿し、Permalink を `posts/log.jsonl` に追記する
8. ユーザーに報告する（画像・順位・Permalink・失敗理由・`alerts_for_owner` の有無）

素材ファイルが足りない場合は、その花を描かずに続行し、`report.json` の `missing` に出る（画像は必ず出力される）。
