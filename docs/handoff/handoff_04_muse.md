### 毎日の合成スクリプト `compose.py`【作成済み・動作確認済み】
使い方: `python3 compose.py --state garden/state.json --assets assets --out out [--gif]`（`make_day0.py` と同じフォルダに置く）

- 入力: `state.json`（v2）、`assets/`（スプライト）。レイアウトと色は `make_day0.py` の定義を使う。
- 出力（媒体ごと）: `<媒体>.png`（1080×1080、フレーム1）、`<媒体>.gif`（2フレーム、`--gif` 指定時）、`<媒体>.alt.txt`（alt 下書き）。全体で `report.json`。
- 空: 生存中の毒花の数で段階が変わる（0輪=水色／1〜2=薄紫／3〜4=紫＋ガスの粒／5以上=暗い紫＋稲妻）。
- 毒花は**1日2輪まで**描く（古い順）。超過分は `flower_mold` 1つにまとめる。
- 素材ファイルが足りない場合は、その花を描かずに続行し、`report.json` の `missing` に素材名を書く。**画像は必ず出力される。**
- 動作確認: `compose_demo/` に、Day 1 を想定したテスト状態（`test_state_day1.json`）と出力3媒体、alt、報告を置いた。毒花が5輪ある Threads は、成体とカビの素材が未作成のため `missing` に出るのが正しい動き。

**state.json の書き方（compose.py が読む形）**
| plots の kind | 必要なフィールド | 使う素材 |
|---|---|---|
| good | `id`、`stage`（sprout / stem / bud / bloom）、bud・bloom のとき `species`（himawari / sakuraso / tulip / kinbara / nohana） | `flower_good_sprout`、`flower_good_stem`、`flower_good_<species>_bud`、`flower_good_<species>_bloom` |
| poison | `id`、`species`（rafflesia / haetori / saboten / chili / blackhole）、`age_days` | `age_days` 0 → `flower_poison_sprout`、1以上 → `flower_poison_<species>` |
| purified | `id`、`species`（元の毒花の種類） | `flower_purified_<species>` |
| mold | `id`、`count` | `flower_mold` |
| empty | `id` | なし |

- 各素材は `_f1.png` / `_f2.png` の2枚組。f2 がなければ f1 で代用。
- 庭ごとの `day`（画面の「DAY n」）、`sun_level`（0〜5、日光バー）、`health`（0〜100、健康度バー）を使う。水と栄養のバーは、任意の `hud: {"water": 0〜1, "nutrition": 0〜1}` で渡す。

**暫定の仮定（要確認）**
1. 毒花は、芽吹いた翌日（`age_days` 1）から成体の姿にする。
2. HUD の水・栄養バーの値の出し方は未定義。当面は、Muse が計算して `hud` に入れる。

## 12. 浄化後の5種、浄化演出、チューリップの色【確定】（2026-11-21 追記）

### チューリップの色のしくみ
- `compose.py` の `tulip_color(garden_name, plot_id, planted_day)` が、植えた花ごとに色（red / yellow / blue）を決める。**ランダムに見えるが、同じ花には必ず同じ色**が出る（再実行してもちらつかない）。336回の試行で、赤105・黄119・青112とほぼ均等。
- **Muse が植えるとき**: `color = tulip_color(庭の名前, 置き場所番号, 植えた日)` を呼び、plot に `"color"` と `"planted_day"` を保存する。
- **保存がない場合**: 描画時に同じ関数で色を導出する（`planted_day` がなければ 0 として扱う）。保存した値があれば、そちらを優先する。
