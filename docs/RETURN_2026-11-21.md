## 4. 依頼4：回答

### 4-1. 司令塔の `compose.py` は最新版か → **旧版です。差し替えてください**
同梱の最新版と比べると、次が足りません。

- `choose_slot(species, occupied, plot_count)`: 新しい植物の置き場所を返す。大型（rafflesia / blackhole / mold）は後列 `[3, 1, 5, 2, 4]`、それ以外は初期3か所＋拡張順
- `tulip_color(garden_name, plot_id, planted_day)`: チューリップの色（red / yellow / blue）。同じ花には必ず同じ色
- チューリップが `color` に応じた素材名になること（旧版では `flower_good_tulip_bloom` を探して素材が見つからない）
- カビ園の置き場所が後列になること、大型が後列以外にあるときの `warnings`

`make_day0.py` は、`large_sprite_slot_order` の1行を除いて同じです。`garden_layout.json` は、この1項目を追加した版を同梱しました。

### 4-2. `make_post.py` が state.json に要求するフィールドは足りるか → **足ります**
司令塔の `state.json`（Day 0 の形）に、`day` を 1 にして実行し、3媒体の文面が生成できることを確認しました（`day` の扱いは下記の②）。必須は次のとおりです。

| フィールド | 備考 |
|---|---|
| `day`、`plots`、`health`、`purify_pool`、`totals.reposts`、`unavailable_metrics`、`yesterday_tally`（`soft` / `prickly` / `neutral` / `excluded`）、`milestones.rainbow` | すべて、司令塔の state.json に既にある |
| `events_today`（`new_poison` / `purified` / `bloomed` のリスト） | 任意。毎日の更新で書く。初期値は `{}` |
| `hud`（`water` / `nutrition`、0〜1） | 任意（`compose.py` が読む）。初期値は省略可。省略すると水・栄養のバーは0 |

追加すべきフィールドは、ありません。ただし次の3点に注意してください。

1. **X の `unavailable_metrics` に `"comment_text"` を入れることを推奨します。** 数字は取得できると確認済みなので、数字の指標は入れなくてよいです。コメント本文は未検証なので、検証が済むまで入れておき、読めると確認できたら外します。入れないと、Xの文面に「ふわふわ0／チクチク0」と出て、コメントを判定したように読めます。入れておけば、文面は「コメントの判定：この媒体では取得できません」になり、浄化の予告も出ません。
2. **`day` は、投稿を作る前に、その日の Day 番号に更新してください。** `make_post.py` は `day` をそのまま見出しに使います。
3. 各庭の `last_post_url` などの余分なフィールド（`handle`、`fence`、`sky`、`plot_count`、`max_plots`、`expansion_order`）は、読み取りでは無視されます。害はありません。

### 4-3. plots の各 kind の最終形（`compose.py` の読み取り仕様）

| kind | 必須 | 任意・補足 | 使う素材 |
|---|---|---|---|
| `empty` | `id` | | なし |
| `good` | `id`、`stage`（`sprout` / `stem` / `bud` / `bloom`） | `bud`・`bloom` では **`species`** が必須（`himawari` / `sakuraso` / `tulip` / `kinbara` / `nohana`）。`tulip` は `color`（`red` / `yellow` / `blue`）と `planted_day` を保存（なければ `tulip_color()` で導出）。`water_progress`、`fed` は司令塔側の管理用（`compose.py` は読まない） | `flower_good_sprout` / `_stem`、`flower_good_<species>_<stage>`、チューリップは `flower_good_tulip_<color>_<stage>` |
| `poison` | `id`、`species`（`rafflesia` / `haetori` / `saboten` / `chili` / `blackhole`）、`age_days`（整数） | `age_days` が 0 なら毒の芽、1以上なら成体（**仮定。未確定**） | `flower_poison_sprout`、`flower_poison_<species>` |
| `purified` | `id`、`species`（**元の毒花の種類**） | | `flower_purified_<species>` |
| `mold` | `id`、`count` | **司令塔が保存する必要はない。** 毒花が3輪以上のとき、`compose.py` が超過分から自動で作り、後列に置く | `flower_mold`（未作成） |

共通の注意:
- `id` は置き場所の番号 1〜14（重複なし）。新しく植えるときは `compose.choose_slot()` で決める。
- 空は、**`poison` の全数**（描画される2輪だけでなく、超過分も含む）で段階が決まる。0=水色／1〜2=薄紫／3〜4=紫／5以上=暗い紫＋稲妻。
- 毒花は、古い順に2輪まで描かれる。
- 大型（rafflesia / blackhole / mold）が後列（1〜5番）以外にあると、`report.json` の `warnings` に出る（画像は出力される）。

## 6. 今回の変更（`make_post.py`）

司令塔の報告にあった事実を、反映しました。

1. **ハッシュタグ `#ことばのかだん` を、全投稿の末尾に追加**（`HASHTAG`）。報告にある「ユーザー指示で全投稿に付ける」に従った。長さの計算に含め、必ず残す。**変えたい場合は `HASHTAG` を空にする。**
2. **Xの上限を、280 から 278 に**。Buffer の計算は、Day 0 + ハッシュタグで 297、`xlen.py` では 296 で、1の差があったため、安全マージンを2とった。
3. 順位が同率のときの表示順を、X・Instagram・Threads に固定（以前は state.json の並び順）。

検証: ランダムな1000通りの状態で、上限超過0件。X の最大は278ちょうど。見出し・自庭・順位・ハッシュタグの4行は、必ず残る。
